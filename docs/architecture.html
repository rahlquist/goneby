GoneBy — Backward Memory Architecture

Retroactive project memory: capture → encrypt → backward walk → embed → store → retrieve

Capture Phase

  • • Zero token cost — disk I/O only
  • • ChaCha20-Poly1305 per-entry encryption
  • • Append-only WAL, no filtering
  • • Called at each context compaction

Backward Walk

  • • One-time cost at project close
  • • Walks newest → oldest (verification)
  • • LLM judges relevance against shipped MVP
  • • Deduplicates by content hash
  • • Keeps ~10-20% of entries

Embed & Store

  • • Qwen3-Embedding-0.6B (local)
  • • MRL 512 dimensions
  • • Valkey (default) or Qdrant
  • • Cosine similarity search
  • • Metadata-tagged vectors

Retrieval

  • • Future sessions query memory
  • • Same embedding model for queries
  • • Semantic search across stored memories
  • • Ranked by relevance score
  • • Cross-project knowledge reuse
